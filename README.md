# @davidsho/cdk-constructs

L3 CDK constructs for deploying Angular apps to AWS, server-rendered or prerendered.

See [CHANGELOG.md](./CHANGELOG.md) for release notes.

## Choosing a construct

| | `AngularStaticDistribution` | `AngularSsrDistribution` |
|---|---|---|
| Angular `outputMode` | `static` | `server` |
| Origin | S3 only | Lambda Function URL, plus S3 for assets |
| Renders | At build time | At request time |
| Cold starts | None | Yes, on cache miss |
| Directory indexes, legacy redirects, 404 status | Viewer-request function and error responses | The Express server in the app |

Reach for `AngularStaticDistribution` unless content genuinely varies per
request: live data, per-user rendering, or anything that has to be fresh at the
moment of the request rather than the moment of the build. A site whose routes
are all `RenderMode.Prerender` does not need an origin application, and paying
for one buys nothing but cold starts.

A contact form is not on its own a reason for SSR. Posting to a third-party
form endpoint from the browser keeps the site static.

## Requirements

- Node.js >= 18
- `aws-cdk-lib` >= 2.243.0
- `constructs` >= 10.5.1

## Install

Hosted on GitHub Packages. Add the following to your `.npmrc`:

```
@davidsho:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=YOUR_GITHUB_PAT
```

A GitHub Personal Access Token with `read:packages` scope is required. Then:

```bash
npm install @davidsho/cdk-constructs
```

## `AngularStaticDistribution`

A prerendered Angular site on S3 behind CloudFront, with no origin compute:

- An S3 origin holding the whole build output, uploaded in three cache-control tiers (fingerprinted assets immutable, images long-lived, HTML revalidated)
- A viewer-request CloudFront Function that resolves directory indexes (`/about` to `/about/index.html`), serves legacy 301s from a build-generated manifest, and redirects non-canonical hosts to the apex
- Custom error responses mapping S3's 403 and 404 to a prerendered 404 page with a real `404` status
- Strict security headers and HSTS, with a user-supplied CSP

The app must be built with `outputMode: 'static'` and needs a concrete `404`
route so the build emits `404/index.html`. A wildcard route alone does not
produce the file.

### Usage

```ts
import * as path from 'path';
import {AngularStaticDistribution, readRedirectManifest} from '@davidsho/cdk-constructs';

const dist = path.join(__dirname, '../../web-app-dist/browser');

new AngularStaticDistribution(this, 'Web', {
    browserDistPath: dist,
    contentSecurityPolicy: buildCsp(),

    domainName: 'example.com',
    certificate,
    hostedZone,

    // Generated by the web app's build; consumed at synth time, not served.
    redirects: readRedirectManifest(path.join(dist, 'redirects.json')),
    excludeFromUpload: ['redirects.json'],
});
```

### Redirects

`redirects` maps legacy path to new path, both root-relative. Lookups are exact,
with trailing-slash tolerance in both directions, so a renamed URL space needs
one entry per page rather than a prefix rule. A key whose target is the key
without its trailing slash is handled without looping.

The manifest is baked into the function source, and CloudFront caps inline
function code at 10 KB. The construct throws at synth time when the manifest
pushes it over, rather than letting the deploy fail.

### Cache tiers

Three `BucketDeployment` passes claim slices of the output by pattern:

| Prop | Default | Cache-Control |
|---|---|---|
| `immutablePatterns` | `*.js`, `*.css`, `*.woff2` | `public, max-age=31536000, immutable` |
| `longLivedPatterns` | image extensions (`*.png`, `*.webp`, `*.svg`, ...) | `public, max-age=2592000` |
| everything else | | `public, max-age=0, must-revalidate` |

`prune` is safe on each pass because the include/exclude filters apply to the
destination scan as well as the source, so the passes do not delete each other's
objects.

## `AngularSsrDistribution`

A single CloudFront distribution that fronts:

- A Lambda Function URL for the default behaviour, running the Angular SSR server via the Lambda Web Adapter
- An S3 bucket for hashed and unhashed static assets (`*.js`, `*.css`, `*.svg`, `*.png`, `*.jpg`, `*.webp`, `*.woff2`, `site.webmanifest` by default)
- A viewer-request CloudFront Function that injects `x-forwarded-host` (and, when a custom domain is set, redirects `www.` to apex)
- Strict security headers and HSTS, with a user-supplied CSP

### Minimal usage (no custom domain)

```ts
import * as path from 'path';
import {AngularSsrDistribution} from '@davidsho/cdk-constructs';

new AngularSsrDistribution(this, 'Ssr', {
    serverDistPath: path.join(__dirname, '../../web-app-dist/server'),
    browserDistPath: path.join(__dirname, '../../web-app-dist/browser'),
    contentSecurityPolicy: "default-src 'self'",
});
```

The site is served from the default CloudFront URL.

### With a custom domain

```ts
const ssr = new AngularSsrDistribution(this, 'Ssr', {
    serverDistPath: path.join(__dirname, '../../web-app-dist/server'),
    browserDistPath: path.join(__dirname, '../../web-app-dist/browser'),
    contentSecurityPolicy: buildCsp(),

    domainName: 'example.com',
    certificate,
    hostedZone,
    additionalDomainNames: ['members.example.com'],
});
```

The certificate must already include every entry in `additionalDomainNames` in its `subjectAlternativeNames`. The construct does not modify the certificate.

### With an API behaviour

```ts
const apiBehavior: cloudfront.BehaviorOptions = {
    origin: new origins.HttpOrigin(apiDomain, {...}),
    // ...
};

new AngularSsrDistribution(this, 'Ssr', {
    // ...
    additionalBehaviors: {'api/*': apiBehavior},
});
```

`additionalBehaviors` is merged in before the static-asset catch-alls, so `api/*` always wins over `*.js` and friends.

### Removal policy

The S3 assets bucket defaults to `RemovalPolicy.DESTROY` with `autoDeleteObjects: true`, because the contents are regenerated on every deploy. If you want the bucket (and its objects) to survive stack deletion, pass `bucketRemovalPolicy: cdk.RemovalPolicy.RETAIN`.

### Extending the SSR Lambda or assets bucket

`ssrFunction` and `assetsBucket` are exposed as public readonly properties. Use them to grant extra permissions, add extra deployments, or attach further integrations:

```ts
const ssr = new AngularSsrDistribution(this, 'Ssr', {...});

mySecret.grantRead(ssr.ssrFunction);

new s3deploy.BucketDeployment(this, 'ExtraAssets', {
    destinationBucket: ssr.assetsBucket,
    sources: [s3deploy.Source.asset('extra-public')],
});
```

## `invalidateCdnStep`

Helper for CodePipeline post-deploy invalidation. Accepts either distribution construct directly, or the `distributionIdOutput` `CfnOutput` each exposes:

```ts
import {invalidateCdnStep} from '@davidsho/cdk-constructs';

pipeline.addStage(stage, {
    post: [invalidateCdnStep(stage.webStack.ssr)],
    // or, equivalently:
    // post: [invalidateCdnStep(stage.webStack.ssr.distributionIdOutput)],
});
```
